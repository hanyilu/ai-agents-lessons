Token 与上下文窗口：LLM 的两项底层原理

模型不读文字，读 token：文本先按高频合并切成 token；生成时模型不是懂词，是算下一个 token 的概率、选一个接回去再重复。窗口是容量，不是记忆：超了就挤出，中间还看不清，账单还按圈数翻倍。这一课讲的是大模型本身的底层原理：它怎么读字、怎么续写、窗口和成本为什么是这样；后面讲注意力、幻觉、训练时，会不断回到这里。

分词机制

BPE 的核心不是“懂词”，而是反复合并高频片段。

经典 BPE 思路从最小符号出发：统计训练语料里相邻片段出现的频率，反复把高频组合并进词表。这样常见字符串用较少 token 表示，罕见字符串仍能退回更小片段，不必依赖一个无限大的词表。

这是一种压缩与开放词表之间的折中，不是语言学意义上的完美分词。一个 token 可能没有独立语义；不同 tokenizer 对同一句话也可能切出不同序列。

初始：l o w · l o w e r
高频合并：l+o → lo
继续合并：lo+w → low
结果：low · low e r
  • 词表是有限集合；未见过的字符串通常被拆成更小单元。
  • 代码、URL、多语言文本的切分效率可能明显不同。
  • 字符数、单词数和 token 数不能互相固定换算。

生成原理

模型不是懂词，是算概率更高的词。

模型不是懂词：它先算下一个 token 的概率分布，选一个接回序列，再重复同样过程。回答看起来一次写成，底层却是一连串逐步决策。

这句话的意思是：一整句话的概率，等于每一步“在前面所有词的条件下出这个词”的概率连乘。早期选了不同的词，后面全部条件都变了，一步走偏，后面可能全偏。

语言很顺，只说明这串词的概率高，不等于事实正确。顺不顺是概率问题，对不对是事实问题，两件事不要混在一起。

Temperature 只改变概率分布的尖锐程度：低温让分布更尖、输出更稳定，高温让分布更平、输出更多样。它不核验事实，调到 0 也不等于不幻觉；关键事实仍要来自数据库、检索或受控工具。

P(t₁…tₙ) = ∏ P(tᵢ | t₁…tᵢ₋₁)
上下文 → 概率分布 → 选一个 token → 追加 → 再预测
  • 同一个早期选择会改变后续全部条件。
  • “语言很顺”只说明序列概率高，不等于事实正确。
  • Temperature 调的是分布尖锐程度，不是事实开关。

机制

窗口是怎么满的

模型不读文字，读 token：一段话先被切成小块，再一块块喂给模型。块数就是这次调用的输入规模，切法不同，块数也不同。

窗口是模型一次能同时看到的块数上限。系统指令、对话历史、工具返回都要占格，格子满了，新块进来就得挤掉最旧的块——不是报错，是静默丢失。

  • 窗口满了不是报错，是静默丢失：被挤掉的内容模型直接看不见。
  • 历史越长，每圈重复输入越多，成本越高。

位置效应

为什么中间会丢

窗口里的位置也有讲究：实测发现模型对首尾的信息更敏感，夹在中间的内容最容易被忽略，这就是 Lost in the Middle：不是模型看不见，是注意力分给了两端。

所以重要的指令和关键证据不要只埋在中间：放开头或结尾，或者在关键步骤前单独拎出来再强调一次，比单纯堆量管用。

  • 长文档塞进窗口 ≠ 模型都用上了。
  • 关键信息放两端，比堆量更管用。
成本

成本是怎么乘出来的

账单公式很简单：token 数 × 单价。但实际使用中往往是多轮循环，每圈都要把历史重新输一遍，圈数一多，费用就按圈数翻倍，演示时看着便宜，上线后账单吓人。

省钱的办法不在换便宜模型那一刻，而在循环设计：能缓存的缓存，能裁剪的裁剪，能提前停的提前停；每圈结束先问一句，还要不要继续。

  • 先算一圈的 token，再乘预期的圈数，才是真实预算。
  • 预算护栏要写进循环：轮数、token、费用三上限。

设计

设计时记住什么

调用模型先定三条线：窗口预算（一次放多少）、轮数预算（最多跑几圈）、费用预算（最多花多少）。三条线写进循环，而不是凭感觉。

窗口不够时优先压缩和裁剪，而不是硬塞；被挤掉的历史要有地方可查，比如摘要或外部存储，而不是直接丢掉——窗口是容量上限，不是记忆。

  • 窗口是容量上限，不是记忆；记忆要另外做。
  • 先定预算，再谈能力。
误区辨析

容量、利用、记忆，别混为一谈。

窗口能放下，不等于模型能答对：容量是“能放多少”，利用是“放进去后用得好不好”。长文档塞满窗口，中间照样可能被忽略，关键信息还是要放两端、做评测。

记忆也不是窗口的同义词：窗口只管这一次能看到多少，跨会话的事实要另外做存储、检索和更新——存在哪里、何时取出来、错了怎么改，都是存储与检索设计，不是把窗口扩大的事。

  • 容量 ≠ 利用：放得下 ≠ 答得对。
  • 记忆 ≠ 窗口：跨会话事实要另外存、另外取、另外改。
要点回顾

这课记住什么

  • 分词是高频合并：常见串用较少 token，罕见串退回小片段；一个 token 未必有独立语义，切法随 tokenizer 而变。
  • 生成是算概率：模型算下一个 token 的分布、选一个接回去再重复；语言顺只说明概率高，不等于事实正确。
  • 窗口是容量上限，不是记忆：满了就静默挤出，不会报错。
  • 关键信息放两端，中间最容易被忽略。
  • 成本 = token 数 × 单价 × 圈数；预算护栏要写进循环。
  • 先定窗口、轮数、费用三条线，再谈能力。
自测

窗口满了之后，新 token 进来会发生什么？

A. 模型报错并停止
B. 最旧的 token 被静默挤出 ✓
C. 窗口自动扩容
D. 新 token 被丢弃
解析：窗口是固定容量的，新内容进来时最旧的内容会被挤出，而且不会报错——这就是静默丢失，也是长任务里历史突然“失忆”的常见原因。
证据

论文与文章

  • Neural Machine Translation of Rare Words with Subword Units（Rico Sennrich, Barry Haddow, Alexandra Birch，ACL 2016）
    支持：分词（BPE）是 token 的来源：文本先被切成子词单元再输入模型，token 数决定输入规模。
    边界：这是机器翻译领域的分词方法，本文用它说明 token 的切分原理，不涉及 Agent 循环本身。
  • Lost in the Middle: How Language Models Use Long Contexts（Nelson F. Liu 等，arXiv 2023）
    支持：长上下文中模型对首尾信息更敏感、中间信息最容易被忽略，是本课位置效应的证据。
    边界：实验用的是问答任务中的长上下文，不是 Agent 循环；结论用于说明位置效应，不直接等于所有 Agent 场景的表现。
  • Attention Is All You Need（Ashish Vaswani 等，NeurIPS 2017）
    支持：支持自回归生成的背景：解码器用掩码注意力逐个算下一个 token 的概率分布，是理解“算概率、选一个、接回去”的起点。
    边界：原论文的主要实验是机器翻译与句法分析；现代 decoder-only LLM 在数据、规模和实现上已经发生变化。
