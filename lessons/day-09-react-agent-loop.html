AI AGENTS 深入学习 · 第 9 天

ReAct 与 Agent 循环：想一想、动一动、看一看，循环转起来

ReAct 把单次调用变成 Thought→Action→Observation 的循环：模型先想（拆解、计划、判断下一步），再动（调工具），看到真实结果后修正下一轮想法，轨迹全部追加进上下文。推理轨迹让计划可追踪，Observation 让模型不用靠猜；但循环本身不会停——Finish、步数上限、重复检测这些刹车必须由后端代码写死，模型只提议、代码才裁决。

2026-11-09 · 约 18 分钟
01 为什么单次调用不够

答案依赖中间结果，单次调用没有“下一步”。

一次调用只能看到调用前的信息：用户说“周五下午有空吗，顺便订个会议室”，模型不查日历就不知道有没有空，不订会议室就不知道订没订上。答案依赖中间结果，中间结果又决定下一步——单次调用没有“下一步”这个位置。

这就是 Agent 循环要解决的问题：把一次调用拆成多轮，每轮模型先想、再调工具、再看结果，看到结果再决定下一轮干什么。循环的每一轮都在回答一个问题：已知这些，下一步该做什么。

  • 单次调用是开环：输入固定，输出一次定型。
  • 多步任务是闭环：每步的结果决定下一步。
  • 循环的本质是“看到反馈再决策”，不是“一次想全”。
02 循环长什么样

一轮三步：想、动、看结果，轨迹全进上下文。

ReAct 规定每轮固定三步：Thought——模型用自然语言写下“现在是什么情况、下一步该干什么”；Action——调一个工具；Observation——工具返回的真实结果。三步写成文本，追加进上下文，下一轮模型全看得到。

循环结束也有固定动作：Finish——模型判断信息够了，停止调用、直接回答用户。从 Thought 到 Finish，整个轨迹就是一次任务的完整记录，人读得懂、机器能回放。

  • Thought 是推理轨迹，Action 是工具调用，Observation 是环境反馈。
  • 轨迹追加进上下文，越往后上下文越长、成本越高。
  • Finish 是模型主动喊停的动作，不是后端猜的。

03 Thought 为什么有用

Thought 是循环里的草稿纸，写下来才算数。

Thought 不是给人看的装饰：它把计划写进上下文，下一轮模型不用重新猜“做到哪了”。第 6 天讲过，推理要落字才能当草稿纸——Thought 就是循环里的草稿纸，写下来才算数。

Thought 还管异常：工具报错、结果出乎意料时，模型先在 Thought 里复盘“刚才哪步错了、换什么策略”，再出下一个 Action。没有 Thought 的 Act-only 模式，模型只会机械地重复上一步。

  • Thought 三个用处：拆解计划、跟踪进度、处理异常。
  • 写进上下文才能被下一轮复用，只在脑子里想等于没想。
  • ReAct 论文：有推理的 ReAct 始终优于纯行动的 Act-only。
04 Observation 怎么纠偏

查到的事实进上下文，幻觉就没了立足点。

Observation 是环境给的真实反馈：日历说 15:00 后空闲，会议室说已订好——这些是事实，不是模型猜的。第 3 天讲过，模型不知道也要选一个词；Observation 把“不知道”换成“查到了”，幻觉就没了立足点。

论文的人工分析很直接：200 条 HotpotQA 轨迹里，CoT 的失败 56% 是幻觉，ReAct 是 0%。ReAct 的主要失败变成搜索结果不好（23%）——问题从“模型编答案”变成了“工具没查到”，这是能修的工程问题。

  • Observation 把猜测换成事实，是循环里唯一的真实来源。
  • 幻觉 56%→0%，代价是失败变成工具问题。
  • 但 Observation 也会错：工具返回的错结果，模型会照单全收。
05 循环在后端怎么实现

循环是后端写的 while，模型只出下一步。

循环本身不是模型的能力，是后端写的一个 while：每轮调一次模型、解析它的 Action、执行工具、把结果拼回 messages，再进下一轮。轨迹、步数、超时都是代码里的变量，模型只负责出下一步。

关键设计是状态要显式：messages 存完整轨迹，step 计数防死循环，started_at 计超时。LangGraph 这类框架做的就是把这套状态机写成图——节点是步骤，边是转移，检查点是断点续跑的快照（第 11 天细讲）。

messages = [system, user]        # 轨迹：每轮追加
for step in range(MAX_STEPS):    # 护栏 1：步数上限
    reply = llm(messages)        # 模型出 Thought + Action
    if reply.is_finish():        # 模型喊停
        return reply.text
    result = run_tool(reply.tool)  # 后端执行工具
    messages += [reply, result]  # Thought+Action+Observation 进轨迹
raise TimeoutError("步数用完仍未完成")
  • 模型出 Thought+Action，后端执行并回填 Observation。
  • 状态显式化：轨迹、步数、超时都要有变量管。
  • 框架只是把这套 while 循环写成状态机。
06 什么时候停

停的条件要写死，模型不会自己停。

循环不会自己停：模型可能一直觉得“还差一点”，调一整夜工具。停的条件必须由代码写死——模型返回 Finish、步数到上限、token 预算用完、总超时到，四条里任何一条触发就停。

Anthropic 的建议很实在：给 Agent 设最大轮数这类停止条件。预算也要分开算：步数管“转几圈”，token 预算管“花多少钱”，超时管“等多久”——三个上限各管各的，缺一个都有洞。

  • Finish 是模型喊停，其余三条是代码强制停。
  • 步数、token、超时三个上限各管各的。
  • 停下来之后要告诉用户“做到哪了”，而不是悄悄返回半成品。
07 循环失控的四种样子

循环在转、任务没进展，就是失控。

最常见的是重复：模型用同一参数调同一个工具，Observation 一模一样，它还继续调——第 8 天讲过的错误回填没写好时就会这样。其次是提前 Finish：信息还没够，模型就觉得够了，交了半成品。

还有两种更隐蔽：Thought 与 Action 脱节——想的是查 A，调的却是 B；错误循环——工具报错，模型不改参数原样再调。共同点都是循环在转、任务没进展，轨迹越长越贵。

  • 重复动作、提前 Finish、想做脱节、报错原样重试。
  • 失控的信号是轨迹变长、任务没进展。
  • 发现失控要靠代码检测，模型自己很难察觉。

08 常见坑与落地

模型提议、代码裁决；反思要配外部信号。

第一，护栏分工：模型只提议，代码才裁决——重复检测、步数上限、敏感动作确认都写在后端，模型说“订好了”不算数，工具返回成功才算数。第二，Observation 要截断：工具返回几万字日志会把窗口挤爆（第 1 天），只留关键字段。

第三，反思要配外部信号：Reflexion 让模型在失败后写反思、下一轮复用，HumanEval 从 80.1% 提到 91%；但没有外部信号的反思会把对答案改错。后端类比：这就是事件循环——while + 状态 + 退出条件，写过服务器主循环就写过 Agent 循环。

  • 模型提议、代码裁决；敏感动作先确认再执行。
  • Observation 截断后再进上下文，别让日志挤爆窗口。
  • 反思要配外部验证信号，没信号的自我纠错会改错。
要点回顾

这课记住什么

  • 单次调用只看最初信息；多步任务要循环：中间结果决定下一步。
  • 一轮 = Thought（想）→ Action（动）→ Observation（看结果），轨迹追加进上下文。
  • Thought 是写进上下文的草稿纸：拆解、跟踪进度、处理异常，下一轮能复用。
  • Observation 是真实反馈：CoT 失败 56% 是幻觉，ReAct 是 0%，主因是搜索结果不好。
  • 循环在后端就是 while：轨迹、步数、超时都是代码管的状态，模型只出下一步。
  • 停的条件要写死：Finish、步数上限、token 预算、超时，缺一个就可能死循环。
  • 失控四种样子：重复动作、提前 Finish、想与做脱节、报错后原样重试。
  • 护栏分工：模型提议、代码裁决；反思要配外部信号，没信号的自我纠错会改错。
自测

循环里模型连续 3 次用同一参数调同一个搜索工具，每次返回同一结果。按本课讲的护栏，后端最该怎么做？

A. 什么都不做，让模型继续调，直到上下文窗口满了再停
B. 重复检测触发后停下，把“已试过 3 次、结果相同，换策略或向用户确认”回填给模型，步数上限兜底 ✓
C. 把搜索工具从工具清单里删掉，逼模型换别的工具
D. 直接拿最后一次结果当答案交差，不告诉用户循环失败了
解析：重复是代码能检测的信号：连续相同 Action 说明模型卡住了，靠它自己很难察觉。叫停后把错因与“换策略或问用户”回填给模型，步数上限是最后一道兜底；放任不管只会烧 token，删工具或悄悄交差都解决不了卡住的问题。
证据

论文与文章

  • ReAct: Synergizing Reasoning and Acting in Language Models（姚顺宇 等，ICLR 2023 2022）
    支持：Thought/Action/Observation 交替进行：推理帮模型定计划、处理异常，行动从外部取信息；HotpotQA 上 ReAct 27.4、CoT 29.4，两者结合 35.1；FEVER 上 ReAct 60.9、CoT 56.3；CoT 失败里 56% 是幻觉，ReAct 是 0%；ALFWorld 成功率比模仿学习高 34 个百分点。
    边界：结构约束会降低推理灵活性，HotpotQA 上 ReAct 略输 CoT；实验用 PaLM-540B 与维基 API，结论随模型与工具变化。
  • Reflexion: Language Agents with Verbal Reinforcement Learning（Noah Shinn 等，NeurIPS 2023 2023）
    支持：失败后把反思写成文字存入情景记忆，下一轮复用：HumanEval pass@1 从 GPT-4 的 80.1% 提到 91%；ALFWorld 完成 130/134 个任务；但只反思不配外部信号时，最难 Rust 题得分 0.52，低于基线 0.60。
    边界：效果依赖评估器质量；自写测试假阳性率高时反而更差，MBPP Python 上 Reflexion 低于基线。
  • Building effective agents（Erik Schluntz、Barry Zhang，Anthropic 工程博客 2024）
    支持：Agent 是模型在循环里自己决定下一步、每步从环境拿 ground truth；建议从最简单的方案起步，给 Agent 设最大轮数这类停止条件，工具层要像设计用户界面一样认真设计。
    边界：工程指南而非对照实验；文中工具生态说明已随时间变化，结论以方法论为准。
