AI AGENTS 深入学习 · 第 15 天

上下文工程：模型只看得到你给它的 token，窗口越大越要省着用

Prompt 工程问的是提示词怎么写，上下文工程问的是每次调用模型该看到哪组 token。Agent 每步都在往上下文里加东西——历史、工具返回、检索结果——窗口再大也会满，塞得越多模型记得越差、越贵、越慢。所以这课的核心只有一个判断：上下文是稀缺的工作内存，不是无限的硬盘，写、选、压、隔四件事，决定 Agent 能走多远。

2026-11-15 · 约 18 分钟
01 为什么是上下文工程

从写提示词到管上下文

Prompt 是一次写好的静态文本，上下文是每轮调用都会变的状态。第 1 天讲过，窗口是容量不是记忆；Agent 跑起来后，系统提示、工具定义、对话历史、工具返回、检索结果全拼进同一份预算，而且每步都在涨。

Anthropic 在 2025 年 9 月给了定义：上下文就是采样时包含的那组 token，工程问题是让这组 token 的效用最大。Prompt 工程只管指令怎么写，是它的子集；上下文工程管全部——什么进、什么留、什么丢、什么时候进。

  • 模型没有后台：没进上下文的东西，对模型等于不存在。
  • 上下文是模型唯一的世界输入：给错了，再强的模型也答不对。
  • 第 8 天的工具定义、第 10 天的记忆，都是上下文工程的零件。
02 Context Rot

窗口越大，记得越差

原理在第 2 天就埋下了：Transformer 里每个 token 都要跟其他所有 token 算注意力，n 个 token 就是 n² 组关系。训练数据里短序列占多数，模型本来就不擅长超长依赖；窗口一变大，关系就被摊薄，recall 先掉。

实测也一样。RULER 测了 17 个模型、13 项任务：纯找针几乎满分，但难度一加、长度一涨就大跌，宣称 32K 以上的模型只有一半在 32K 还达标。Chroma 2025 年测 18 个模型、8 种长度：任务难度不变、只加长度，表现一致下滑。这就是 context rot。

  • 宣称长度 ≠ 有效长度：能装 1M token，不等于能用好 1M token。
  • 针能找到 ≠ 推理还准：检索满分，照样可以在多跳推理上翻车。
  • Lost in the Middle（第 1 天）：关键信息放中间，最容易被漏掉。

03 上下文的解剖

四块拼图抢一份预算

每轮调用的上下文由四块拼成：系统提示（身份、规则、格式）；工具定义（名字、描述、参数表）；对话历史（用户消息，加上模型自己的 Thought 与工具调用）；外部数据（RAG 片段、文件内容、工具返回）。四块抢同一份注意力预算。

其中历史是唯一会自己长大的。一次 ReAct 循环（第 9 天）就加一轮 Thought、一次工具调用、一条 Observation；跑 30 步，历史能吃掉大半窗口。不管理，它就是默认的最大头。

  • 工具定义常被低估：第 8 天讲过，工具越多、描述越长，选错的概率越高。
  • 外部数据最不可控：RAG 塞 10 个片段，可能 9 个都是噪音。
  • 系统提示是地基：写错一次，每轮调用都跟着错。
04 写

先把每块写瘦

系统提示要找正确高度：太细，是把业务逻辑硬编码进提示词，又脆又难维护；太粗，是假设模型跟你有共享语境。Anthropic 的建议是分节加 XML 标签或 Markdown 标题，信息最小但完整——最小不是最短，是够用为止。

工具返回也要省 token：只返回模型下一步需要的字段，别返整张表；工具之间去重叠，描述写清什么时候用，别写这是什么。Few-shot 别堆边角案例，挑几个能代表行为的典型例子就够了。

  • 先测最小提示词：用最强模型跑，失败了再按失败模式加指令。
  • 边角案例进评测集，不进提示词；提示词越长，重点越抓不住。
  • 工具返回先截断、再摘要，最后才考虑给全文。
05 选

按需加载，别预加载

旧做法是预检索：调用前先把可能用到的文档全塞进上下文。Agent 的做法是 JIT：上下文里只留轻量索引——文件路径、查询语句、链接——模型需要时自己调工具去取。Claude Code 对付大代码库就是这么干的：写查询、存结果、用 head、tail 抽查，从不把整个库塞进去。

这就像人查资料：你不会背整本手册，你记的是手册在书架第几层。代价是慢：运行时探索比预取多几步；没给好工具和启发式，模型会逛死胡同、浪费上下文。所以最常见的是混合：高频必备的上来就给，低频的现用现取。

  • 渐进披露：文件大小、命名、时间戳本身就是信号，模型能一层层摸清结构。
  • 索引即上下文：路径和文件名会说话，别急着把内容也塞进来。
  • 探索要配护栏：步数上限、去重、失败回退，用第 9 天的刹车。
06 压

长任务的三招：压

任务长到 token 数超过窗口时，有三招。第一是压缩：窗口快满时让模型把历史摘要成要点，开新窗口继续跑，Claude Code 还会保留最近访问的 5 个文件。第二是结构化笔记：Agent 定期把进展写进外部文件，跨窗口不断线。第三是子 Agent，见下一节。

压缩的取舍在留什么：先求召回，把所有相关信息都抓进摘要，再求精确，删掉多余内容。最轻量的一招是清工具结果：几十步前的原始返回，模型其实再也不需要。但压得太狠会丢当时不重要、后来很关键的细节。

  • 压缩是高保真摘要，不是删帖：决策、未解问题、关键数字必须留。
  • 笔记是外部记忆（第 10 天），摘要是窗口内重启，两件事别混了。
  • 三招可叠加：笔记 + 压缩 + 子 Agent，各管一段。

07 隔

子 Agent：隔离换清晰

不让一个 Agent 背全项目：主 Agent 拿计划、做协调，子 Agent 各领一个干净的小窗口去深挖——查代码、跑分析、找资料。子 Agent 可能啃掉几万 token，但只回主 Agent 一份 1,000–2,000 token 的浓缩摘要，细节留在自己的窗口里。

这就是进程隔离、微服务的思想：隔离换清晰，代价是交接。每次交接都可能丢信息、放大幻觉（第 11 天讲过），所以摘要要结构化：结论、证据、未解决项三段，缺一不可。并行探索赚得到速度，也付得出账单。

  • 主 Agent 只做综合与判断，不直接碰原始材料。
  • 子 Agent 之间不共享上下文，互不干扰，各查各的。
  • 选型看任务：长对话用压缩，里程碑清晰用笔记，并行探索用子 Agent。
08 落地

落地：给上下文立预算

上下文工程落到工程上，就是一张预算表：给每部分定上限，超了就触发压缩或丢弃；每步记 token 数、每类来源的占比，跑评测集看砍掉哪块最不伤分。预算不是拍脑袋：先量（第 13 天的观测），再定。

常见坑三件：全量历史原样追加——默认行为就是默认灾难；把边角案例全塞进提示词——提示词越长，重点越抓不住；压缩丢关键事实——摘要里没写已确认的决策，下一窗口就会推翻重来。

def build_context(parts, budget=100_000):
    ctx, used = [], 0
    for part in sorted(parts, key=priority):
        if used + part.tokens > budget:
            part = compact(part)  # 摘要或截断，禁止静默丢弃关键项
        ctx.append(part); used += part.tokens
    if used > budget * 0.9:
        trigger_compaction()
    return ctx
  • 预算要写进代码，不是写进文档：超了自动触发，别靠人盯着。
  • 压缩触发点设在 80%–90%，别等满了再动手。
  • 模型升级后预算也要重测：新模型的有效长度和旧模型不一样。

这课记住什么

  • 上下文是采样时包含的那组 token——模型只看得到你给它的，别的等于不存在。
  • 窗口越大越要省：context rot 让 recall 随长度下滑，RULER 只有一半模型在 32K 还达标。
  • 好上下文的标准：最小的高信号 token 集——够用为止，不是越全越好。
  • 写瘦：系统提示找正确高度，工具返回只给下一步需要的字段。
  • 按需加载：上下文里留索引不留全文，模型现用现取（JIT），混合策略最常见。
  • 长任务三招：压缩、结构化笔记、子 Agent——子 Agent 只回 1,000–2,000 token 摘要。
  • 隔离换清晰：主 Agent 只看摘要做综合，交接处要结构化摘要防信息丢失。
  • 落地靠预算：每部分定上限、超了触发压缩，80%–90% 就动手，别等满。
自测

你的 Agent 跑 40 步长任务，上下文快满了，历史里有 30 步工具调用记录。按本课的做法，第一步最该做什么？

A. 把窗口换成更大的模型，直接硬扛
B. 让模型把历史压缩成摘要，只留关键决策与未解问题，再开新窗口继续 ✓
C. 把全部 30 步记录原样保留，删掉系统提示腾地方
D. 把任务拆成 40 个独立调用，每次从头开始
解析：窗口再大也有 context rot，硬扛又贵又不准；系统提示是地基不能删；拆成独立调用会丢连续性。压缩是第一杠杆：摘要先保召回再求精确，关键决策与未解问题必须留下来。
证据

论文与文章

  • Effective context engineering for AI agents（Prithvi Rajasekaran, Ethan Dixon, Carly Ryan, Jeremy Hadfield (Anthropic Applied AI team)，Anthropic Engineering 2025）
    支持：定义上下文为采样时包含的 token 集合，提出最小高信号 token 集原则；解释 context rot 与 n² 注意力成因；给出 JIT 检索与渐进披露做法；长任务三招：压缩、结构化笔记、子 Agent。
    边界：工程博客，非同行评审论文；结论来自 Claude Code 等生产实践；子 Agent 回 1,000–2,000 token 是其经验值，不同任务会变。
  • RULER: What's the Real Context Size of Your Long-Context Language Models?（Cheng-Ping Hsieh, Simeng Sun, Samuel Kriman, Shantanu Acharya, Dima Rekesh, Fei Jia, Yang Zhang, Boris Ginsburg，COLM 2024 2024）
    支持：17 个长上下文模型、13 项任务；纯找针几乎满分，但难度与长度一涨就大跌；宣称 32K 以上的模型只有一半在 32K 还能达标。
    边界：合成基准，真实 Agent 任务的衰减形态可能不同；测的是 2024 年的模型，新模型的有效长度已有变化。
  • Context Rot: How Increasing Input Tokens Impacts LLM Performance（Chroma Research Team，Chroma Research 2025）
    支持：18 个模型、8 种输入长度；任务难度固定、只加长度，表现一致下滑；干扰项与问答相似度会加速下滑。
    边界：技术报告，非同行评审论文；用 GPT-4.1 当裁判打分，结论依赖裁判质量；测的是 2025 年中的模型。
