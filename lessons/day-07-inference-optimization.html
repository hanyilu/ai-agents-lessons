推理优化：让模型跑得更快、更便宜的四把刀

生成一个 token，模型要把全部权重从显存读一遍——推理的瓶颈是显存带宽，不是算力。KV Cache 用显存换重复计算，量化把权重变小、读得更快，连续批处理让一次读权重服务更多请求，推测解码让一次前向多出几个 token。四把刀都不改模型本身，只改系统怎么排布计算与内存；但每把刀都有代价：缓存吃显存、量化丢精度、批处理抬延迟，优化前要先量出瓶颈在哪。

01 为什么推理慢

一次前向只出一个 token，瓶颈在显存带宽。

模型生成文本是逐 token 的：第 1 天讲过，自回归一次前向只出一个 token。回答 100 个词，就是 100 次前向；每次前向都要把全部权重从显存读进计算单元——70B 的 FP16 模型约 140GB，读一遍就是一次大搬运。

训练时一次前向算几千个 token，矩阵乘法把算力吃满；推理时一次只算一个新 token，变成矩阵乘向量，算力大量空转，等的是显存把权重搬过来。所以推理优化的第一性原理就三句：少读权重、少重复算、一次读多服务几个请求。

  • 一次前向只出一个 token，100 词就是 100 次前向。
  • 每次前向读全部权重：70B FP16 模型约 140GB。
  • 解码是显存带宽瓶颈，不是算力瓶颈。
02 KV Cache 是什么

K、V 只算一次，存下来复用。

第 2 天讲过注意力：每个新 token 都要和前面所有 token 算分数。如果每步都从头算，生成第 100 个词要把前面 99 个词的 K、V 全算一遍，越往后越慢。KV Cache 就是把每个 token 算过的 K、V 存下来：新 token 只算自己的 K、V，再和缓存里的拼起来算注意力。

代价是显存：每个 token 的 K、V 大小 = 2（K 和 V）× 层数 × 隐藏维度 × 每个数的字节数。vLLM 论文的例子：OPT-13B 每个 token 约 0.8MB，2048 个 token 的请求要 1.6GB 缓存。序列越长、并发越高，缓存越大——省了计算，账单换了个地方记。

  • KV Cache：每个 token 的 K、V 只算一次，存下来复用。
  • 缓存随序列长度线性涨：2 × 层数 × 隐藏维 × 字节数。
  • 省了重复算，但显存成了新瓶颈。
03 KV Cache 的浪费

分页：缓存像操作系统分内存那样管。

旧系统给每个请求预留一整块连续显存，按最大长度算：留 2048 个位置，实际只生成 600 个，剩下 1448 个位置在整个生命周期里都空占着；不同长度的请求拼在一起还会产生碎片。vLLM 论文实测：旧系统只有 20.4%–38.2% 的 KV 显存真正在存 token，六七成被浪费。

PagedAttention 借操作系统的虚拟内存：把缓存切成固定大小的块（比如 16 个 token 一块），用块表映射逻辑块到物理块，用多少拿多少；系统提示等公共前缀只存一份、多请求共享；采样分支用写时复制。实测利用率升到 96.3%，同等延迟下吞吐提高 2–4 倍。缓存总量没变，只是管好了。

  • 旧办法按最大长度预留整块：空占 + 碎片，只用 20–38%。
  • 分页：固定块 + 块表映射，用多少拿多少，浪费不到一块。
  • 前缀共享 + 写时复制：公共提示只存一份。

04 量化

权重变小，读得更快。

权重从 FP16（2 字节）压到 INT4（半字节），70B 模型从 140GB 变成约 35GB，每次前向读的数据减到四分之一，解码变快。GPTQ 用二阶信息逐层量化、把误差补到未量化的权重上，175B 模型 4 个 GPU 小时压到 3–4 bit，精度几乎不掉，A100 上实测提速约 2 倍。

难在离群值：少数权重和激活特别大，粗暴取整会把误差放大。AWQ 的思路是保护约 1% 的关键权重通道——先放大再量化，推理时再除回来，等价于给关键通道更高精度。取舍很直白：INT8 几乎无损、INT4 是生产甜点、再往下是精度悬崖；量化后一定要用自己的评测集重测，不能只看困惑度。

  • FP16→INT4：70B 从约 140GB 压到约 35GB，读权重更快。
  • GPTQ：3–4 bit、175B 约 4 GPU 小时，精度几乎不掉。
  • AWQ：保护约 1% 关键通道；INT4 是甜点，再低是悬崖。
05 批处理

每出一个 token，batch 就重组一次。

批处理是摊薄读权重成本的办法：一次前向读一遍权重，同时给 32 个请求各出一个 token。但静态批处理要等整批都跑完：10 个词的请求要等 1000 个词的邻居跑完才释放位置，短请求被长请求拖死，GPU 大量时间在等。

Orca 把调度粒度从“请求”改成“一次迭代”：每生成一个 token，调度器就重组 batch——跑完的出队、新到的进队，权重只读一遍、服务整批。实测同等延迟下吞吐比 FasterTransformer 高 36.9 倍。代价：批越大，单个请求的词间延迟越高；长请求还会拖慢整批的节奏。

  • 静态批处理：等最慢的跑完，短请求被长请求拖死。
  • Orca：每出一个 token 就重组 batch，新到的随时进。
  • 代价：批越大，单个请求的词间延迟越高。

06 两段延迟

Prefill 吃算力，Decode 吃带宽。

一次请求分两段：Prefill 把整个提示一次性算完，是矩阵乘矩阵、算力密集，决定首词延迟（TTFT）；Decode 一次一个 token，是矩阵乘向量、带宽密集，决定词间延迟（TPOT）。两段瓶颈不一样，混在一个队列会互相拖：一个超长提示的 prefill 会堵住后面所有人的 decode。

所以现代引擎把两段拆开：chunked prefill 把长提示切成小块、插进 decode 的间隙里；更进一步做 PD 分离，让 prefill 和 decode 跑在不同的 GPU 上。看延迟要看两个数：TTFT 决定用户多久看到第一个字，TPOT 决定读起来卡不卡——只看总时长会把问题藏起来。

  • Prefill：一次算完提示，算力密集，决定首词延迟 TTFT。
  • Decode：一次一个 token，带宽密集，决定词间延迟 TPOT。
  • 长提示的 prefill 会堵住 decode：切块或 PD 分离。

07 第四把刀与成本账

小模型猜、大模型验；先算账再动手。

还有一把刀不碰内存、改的是串行本身：推测解码让小模型先猜接下来几个 token，大模型一次前向全部验算——猜对的白拿、猜错的从第一个错处重算，输出分布和原来完全一样。Leviathan 等人在 T5-XXL 上实测提速 2–3 倍。猜对率决定一切：小模型猜不准的任务，这招不赚反亏。

最后算总账：Agent 的成本不是价目表，是 token 数 × 单价 × 循环次数。长思考链、多采样、工具调用，每一步都在乘 token。先量瓶颈再动手：首词慢看 prefill，词间卡看 decode 与 batch，账单高看缓存命中与 token 总量——没量就动手，等于没看火焰图就调优。

  • 推测解码：小模型猜、大模型验，输出不变，T5-XXL 提速 2–3 倍。
  • Agent 成本 = token 数 × 单价 × 循环次数，优化直接省账单。
  • 先量瓶颈再动手：首词、词间、账单各有各的指标。
08 常见坑与落地

四把刀，四条红线。

第一，量化不是免费午餐：代码、数学这类精度敏感的任务对量化更敏感，换了量化模型必须重跑自己的评测集，只看困惑度会漏掉。第二，KV Cache 不是无限的：长上下文加高并发，缓存会先爆，超了就排队或驱逐——第 1 天的窗口满了会丢内容，在服务端就是请求被顶掉。

第三，批处理越大不一定越好：吞吐上去了，单个用户词间延迟也上去了，交互场景要设上限。第四，缓存共享有隐私边界：不同用户的前缀缓存不能混用，只在同一系统提示、同一租户内共享。后端类比：这就是后端性能优化——缓存、压缩、批量、拆分，同一套打法，对象从 SQL 和 HTTP 换成 token 和显存。

  • 量化后重跑自己的评测集，别只看困惑度。
  • KV Cache 会爆：长上下文 + 高并发先算缓存账。
  • 批处理抬延迟、缓存共享有隐私边界，先定上限再上线。
要点回顾

这课记住什么

  • 推理的瓶颈是显存带宽：一次前向只出一个 token，每步都要把全部权重读一遍。
  • KV Cache：每个 token 的 K、V 只算一次存下来复用，大小随序列长度线性涨，OPT-13B 每 token 约 0.8MB。
  • PagedAttention：分页 + 块表 + 前缀共享 + 写时复制，利用率从 20–38% 升到 96.3%，吞吐 2–4 倍。
  • 量化：FP16→INT4，70B 从约 140GB 到约 35GB；GPTQ 压到 3–4 bit 精度几乎不掉，AWQ 保护约 1% 关键通道。
  • 连续批处理：Orca 把调度粒度改成一次迭代，跑完出队、新到进队，吞吐比 FasterTransformer 高 36.9 倍。
  • Prefill 吃算力、Decode 吃带宽：TTFT 与 TPOT 是两个延迟指标，长提示 prefill 会堵 decode。
  • 推测解码：小模型猜、大模型一次验算，输出不变，T5-XXL 提速 2–3 倍；猜对率决定收益。
  • 先量瓶颈再动手：首词慢看 prefill、词间卡看 decode 与 batch、账单高看 token 总量；量化后重跑自己的评测集。
自测

线上 Agent 服务高峰期，用户抱怨回答出得慢、词与词之间还卡。按本课讲的机制，最优先做的事是？

A. 把模型换成更大的参数版本，提高单次回答质量
B. 先分清是首词慢还是词间卡，再看 prefill、KV 缓存与 batch 哪一段是瓶颈 ✓
C. 把 batch 调到最大，吞吐越高用户体感一定越好
D. 直接把所有权重压到 2 bit，显存越小一定越快
解析：慢有两种：首词慢是 prefill 的问题，词间卡是 decode 带宽或 batch 的问题；没分清就动手等于没看火焰图调优。换大模型更慢、batch 拉满抬延迟、2 bit 精度悬崖，都踩了本课讲的坑。
证据

论文与文章

  • Efficient Memory Management for Large Language Model Serving with PagedAttention（Woosuk Kwon 等，SOSP 2023 2023）
    支持：旧系统只有 20.4%–38.2% 的 KV 显存真正在存 token，OPT-13B 每 token 约 0.8MB、2048 token 的请求约 1.6GB；PagedAttention 用分页与块表把利用率提到 96.3%，同等延迟下吞吐提高 2–4 倍。
    边界：只解决缓存管理问题，不缩小缓存总量；收益随负载与基线变化，块大小要调。
  • GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers（Elias Frantar 等，arXiv 2022）
    支持：用近似二阶信息逐层量化并补偿误差，175B 模型约 4 个 GPU 小时压到 3–4 bit，精度几乎不掉；A100 上端到端推理提速约 2 倍。
    边界：只压权重、不压激活；量化本身不减少计算量，只减少内存搬运，2 bit 以下精度会明显掉。
  • Orca: A Distributed Serving System for Transformer-Based Generative Models（Gyeong-In Yu 等，OSDI 2022 2022）
    支持：迭代级调度把调度粒度从请求改成一次解码迭代，配选择性批处理；同等延迟下吞吐比 FasterTransformer 高出 36.9 倍。
    边界：实验用合成流量 trace；收益来自调度与批处理，模型本身的输出与精度不变。
