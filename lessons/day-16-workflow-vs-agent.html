AI AGENTS 深入学习 · 第 16 天

工作流还是 Agent：先问能不能写死，再问要不要自主

工作流与 Agent 的分界在控制流归谁：能写死步骤、要求结果一致、副作用不可逆的任务用工作流；路径依赖执行中发现的信息、且结果可校验的任务才值得上 Agent；最常见的生产形态是工作流为骨、Agent 为关节，升级与降级都要看实测信号而非演示。

2026-11-16 · 约 18 分钟
01 分界

分界在控制流归谁

工作流里，LLM 与工具按预先写好的代码路径走：下一步是什么、调哪个工具、走哪条分支，全写在代码里。Agent 里没有这张路线图：模型看完上一步的结果，自己决定下一步调什么工具。

后端类比很好懂：工作流像状态机或流水线，if/else 与 DAG 写死；Agent 像事件循环里插了一个会判断的调度器——模型当调度器，代码只负责执行、校验与收尾。

  • 同一批零件，两种系统：工具、模型都一样，变的只是谁决定下一步。
  • 第 9 天的 ReAct 循环就是 Agent 的最小形态；第 11 天的状态图就是工作流的骨架。
  • 分界不在用了几个模型，在控制流握在谁手里。

02 工作流五式

先认清五种工作流

链式把任务拆成固定步骤，前一步的输出进下一步，中间能加程序校验门；路由先分类、再分流到专用提示词与工具，避免一个提示词顾此失彼；并行把独立子任务同时跑，或同一任务跑多遍投票聚合。

编排者-工人由中央 LLM 动态拆任务、分给工人再汇总，子任务不预定义；评估-优化是一个生成、一个打分反馈，循环打磨。五式有个共同点：路线是代码定的，模型只在节点里干活。

  • 链式用延迟换准确率：每步变简单，整体更准。
  • 路由的前提是分类分得准，分错了后面全错。
  • 评估-优化的前提是有可判的评价标准，没标准就别循环。
03 Agent 的机制

Agent 只是一条带判断的循环

Agent 拆开看毫不神秘：模型看上下文定下一步，输出一段结构化 JSON；确定性代码执行工具调用；结果拼回上下文；循环直到模型说完成。12-Factor 的说法很准：工具调用就是结构化输出，执行永远在代码手里。

循环能转下去靠两样：每步都要从环境拿 ground truth——工具返回、代码执行结果——而不是模型自己脑补进展；还要有刹车：最大步数、重复检测、敏感动作的人工确认点。

  • 模型提议、代码裁决：分工在第 8 天就讲过。
  • 没有 ground truth 的循环，等于闭眼开车。
  • SWE-bench 编码 Agent 是典型例子：改多个文件，步数事先算不出来。
04 代价账本

自主不是免费的：三笔账

第一笔是延迟与成本：Agent 拿多轮调用换任务表现，步数不可预测，账单按步数乘出来；同样任务，工作流固定几次调用就能结账。第 12 天的成本公式在这里直接生效。

第二笔是误差累积：每步的幻觉与选错都会进上下文，成为下一步的输入，错上加错。第三笔是可测性：同一输入两次跑可能走不同路，回归测试难写。Anthropic 的建议是沙箱里充分测试再上线，再加护栏。

  • 步数 × 单步成本 = 账单，步数不可预测，账单就不可预测。
  • 错一步，后面全跟着错：上下文记住了错误。
  • 测不了就别急着上生产：演示成功一次不算数。

05 五个问题

定型之前先答五道题

定型之前先答五道题：步骤能不能写下来？路径能不能预先知道？结果能不能程序化校验？副作用可不可逆、能不能重做？延迟与成本预算扛不扛得住多轮调用？

前三题答“是”，走工作流；路径依赖执行中才知道的信息、且结果可校验，Agent 才值得。开放式问题、步数无法预知，是 Agent 的主场；要求结果一致、副作用不可逆，是工作流的地盘。

  • 能写死就别上 Agent：写死的每一步都是省下的钱和风险。
  • 可校验是 Agent 的入场券：验不了的结果不敢交给自主循环。
  • 预算先算再动手，别等账单来了再降级。

五道定型题

前两题答“是”就走工作流；路径依赖执行中信息、且结果可校验，才上 Agent。

06 混合形态

生产常态：工作流为骨，Agent 为关节

现实里很少有纯血系统：大多数自称 Agent 的产品，主体是确定性代码，只在需要判断的地方插 LLM。骨架用工作流定死顺序、校验与审批，关节处放一个小 Agent 处理不确定性。

编排者-工人就是典型混合：外层固定流程，内层 orchestrator 动态拆任务；第 11 天的状态图同理——模型只在节点里提议，去向由代码裁决。Agent 要小、要专注，工具与步数都要设上限。

  • 骨架管顺序与审批，关节管判断。
  • Agent 越小越可控：小循环好测、好停、好回滚。
  • 第 15 天的子 Agent 隔离也是同一思想：隔离换清晰。
07 升降级

升级与降级都有信号，别凭感觉

升级信号有两条：工作流里分支越补越多、新情况总在流程外面；评测显示 Agent 版在同等成本下成功率明显更高。Anthropic 的铁律：只有可证明的改进，才值得加复杂度。

降级信号有三条：Agent 开始绕圈、重复调同一工具；账单随步数失控；同一输入结果飘忽、回归测不稳。这时把 Agent 退回成工作流：把走通的路径写死，只留真正不确定的关节给模型。

  • 升：分支补不完 + 评测赢了。
  • 降：绕圈、账单失控、结果飘。
  • 每次改动都要跑评测集（第 13 天），感觉不算证据。
08 落地

落地：控制流要握在自己手里

不管选哪边，控制流必须握在你自己的代码里：循环条件、终止规则、分支逻辑、审批点，写在能读、能测、能改的地方，别藏进框架黑盒。框架可以帮你起步，但要看得懂它底下在干什么。

兜底清单：最大步数、超时、重复检测、沙箱测试、敏感动作人工确认、每次运行留 trace。最后回到起点：先从最简单的方案起步，只在简单方案不够时才加复杂度。

def run(task):
    state = init(task)
    steps = 0
    while not done(state):            # 循环、终止，代码说了算
        step = llm.next_step(state)   # 模型只提议下一步
        state = dispatch(step, state) # 执行、校验、记账都在代码里
        steps += 1
        if steps > MAX_STEPS:
            break                     # 刹车长在代码里，不在模型嘴里
    return state
  • 模型提议、代码裁决：这条分工线永远别让渡。
  • 循环、终止、审批都写进代码，别只写进提示词。
  • 简单起步，实测驱动升级：复杂度是挣来的，不是预支的。
要点回顾

这课记住什么

  • 分界在控制流归谁：工作流的下一步写在代码里，Agent 的下一步由模型现定。
  • 五种工作流——链式、路由、并行、编排者-工人、评估-优化——路线都是代码定的，模型只在节点里干活。
  • Agent 只是一条带判断的循环：模型定下一步、代码执行、结果回上下文，直到说完成。
  • 自主有三笔账：延迟与成本按步数乘、误差一步步累积、可测性变差。
  • 五道定型题：步骤能写死、路径能预知、结果能校验、副作用可逆、预算扛得住。
  • 生产常态是混合：工作流为骨、Agent 为关节，Agent 要小、要专注。
  • 升级看评测赢没赢，降级看绕圈、账单与结果飘不飘，感觉不算证据。
  • 控制流握在自己手里：循环、终止、审批写进代码，简单起步、实测驱动。
自测

客服退款流程固定（查订单→核对政策→退款→回执），偶尔遇到政策没覆盖的特殊情况。按本课做法，最合适的结构是？

A. 全程 Agent，让模型自己决定每一步
B. 全程写死工作流，特殊情况直接拒绝
C. 工作流为骨：固定步骤走代码，特殊情况分流给小 Agent 判断，退款动作过人工确认 ✓
D. 不用 Agent，全部改成人工处理
解析：固定步骤写死最稳、最便宜、最好测；不确定只留在关节处给小 Agent；退款不可逆，必须过人工确认门。全程 Agent 又贵又难测，全写死则特殊情况无路可走。
证据

论文与文章

  • Building effective agents（Anthropic，Anthropic Engineering Blog 2024）
    支持：工作流按预定义代码路径编排 LLM 与工具，Agent 由模型动态主导自己的过程与工具使用；建议先找最简单方案、只在必要时增加复杂度；agentic 系统常以延迟与成本换取任务表现；Agent 适用于难以预知步骤数的开放式问题，误差可能累积、需沙箱测试与护栏。
    边界：基于客户实践的工程经验总结，不是受控实验；模式适用性需结合自身评测验证。文章 2024 年 12 月发表，页面本身注明此后工具生态已有变化。
  • ReAct: Synergizing Reasoning and Acting in Language Models（Shunyu Yao, Jeffrey Zhao, Dian Yu, Nan Du, Izhak Shafran, Karthik Narasimhan, Yuan Cao，arXiv 2022）
    支持：Thought/Action/Observation 循环让模型交错推理与行动，工具返回作为下一步推理的依据；HotpotQA 与 Fever 实测中 ReAct 的幻觉率显著低于纯 CoT。
    边界：论文实测集中在问答与推理基准，生产 Agent 的长循环还需额外护栏；数字来自 2022 年的模型。
  • 12-Factor Agents: Principles for building reliable LLM applications（Dex Horthy (HumanLayer)，HumanLayer 2025）
    支持：大多数自称 Agent 的产品主体是确定性代码、只在关键处插 LLM 判断；Agent 循环可拆成模型定下一步、代码执行、结果回上下文三步；Factor 8 要求把控制流握在自己手里，Factor 10 要求 Agent 小而专注。
    边界：原则清单来自作者与上百位创业者的实践访谈，非受控实验；“工具少于 100 个、步数少于 20 步”是经验值，需按自身任务验证。
