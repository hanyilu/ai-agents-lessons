AI AGENTS 深入学习 · 第 6 天

推理与思维链：为什么多写几步，答案就变准了

模型一次前向只算一个 token 的概率分布，多步推理塞不进一次计算。CoT 是把中间步骤写进上下文：每一步都是模型本来就会的简单预测，中间结果还能被后面的步骤回看，多写一个 token 就是多一次前向。推理时计算拿 token 换准确率——更长思考、更多采样、更深搜索，按难度分配最划算；但长链也会放大错误、烧掉预算，所以要配验证器与预算，自我纠错没有外部信号只会原地打转。

2026-11-06 · 约 18 分钟
01 为什么直接答会错

多步推理，一次前向算不完。

23 个苹果吃掉 5 个又买 12 个，还剩几个？直接问，模型常给错答案。不是它不会减法，是自回归模型一次前向只算一个 token 的概率分布：答案要一次猜中，中间没有地方放草稿。

后端类比：像要求一个函数一次调用算完三层嵌套逻辑、中间不许用局部变量。心算三位数乘法不让打草稿，人也会错——模型缺的不是知识，是放中间结果的地方。

  • 一次前向只算一个 token 的概率分布，算不完多步推理。
  • 直接答错的不是知识，是没有中间步骤可写。
  • 模型需要草稿纸：把中间结果写下来，再继续算。
02 CoT 是什么

先写步骤，再给答案。

CoT 就是让模型先把中间推理步骤写出来，再给最终答案。做法很简单：在 few-shot 范例里，每道例题都附上一步步的解法，模型会照着也写步骤；或者直接在问题后加一句“一步一步想”，大模型也常常开始拆解。

关键在：步骤是模型自己生成的 token，写进上下文就成了下一步的输入。第 1 天讲过，模型只会算下一个 token 的概率——CoT 没有给模型新能力，只是把一道难题换成了一串它本来就会的简单预测。

  • few-shot CoT：范例带步骤；zero-shot：一句“一步一步想”。
  • 步骤是模型自己生成的 token，写进上下文继续用。
  • 不改模型、不改训练，只改 prompt 里的示范。
03 为什么有效

草稿纸的三个作用。

第一，拆解：每一步只做一次加减、一次查表，是模型一次前向能算准的简单预测；难在组合，不在单步。第二，记忆：中间结果 18 写进上下文，后面的步骤不用凭空记住它，注意力可以直接回看——第 2 天讲的注意力机制就是干这个的。

第三，算力：多写一步，就多一次前向计算。推理 token 就是推理时间：写 100 个 token 的思考，相当于给了模型 100 次“想一想”的机会。Wei 等人的实验里，PaLM 540B 在 GSM8K 上从 17.9% 涨到 56.9%，靠的就是 8 条带步骤的范例。

  • 拆解：难推理变成一串简单预测。
  • 记忆：中间结果进上下文，后面可回看。
  • 算力：每多一个 token，就是多一次前向。

04 推理时计算

token 就是算力，难度决定花多少。

训练时花算力是把能力压进参数，推理时花算力是把能力“想”出来：更长的思考链、更多的采样、更深的搜索，都是推理时计算。Snell 等人 2024 年的发现是：按题目难度分配才划算——难题多想、简单题少想，比固定的 best-of-N 做法效率高出 4 倍以上。

换个角度：推理时计算可以部分替代参数规模。在总计算量相当的前提下，小模型配足推理计算，能超过 14 倍大的模型——前提是小模型本身有一定成功率，完全不会的题，想再久也没用。预算要花在“差一点就对”的题上。

  • 推理时计算等于更长思考链加更多采样加更深搜索。
  • 按难度分配：难题多想、简单题少想。
  • 小模型加足够推理，可超 14 倍大模型（有前提）。

05 自我验证

一条链会错，多数票来兜底。

贪心解码只取概率最高的链，一步算错就全错。自洽性换个做法：同一题用较高温度采样很多条推理链，每条链各自算出答案，最后数票——出现次数最多的答案胜出。Wang 等人测下来，GSM8K 在 CoT 基础上又涨了 17.9 个点。

为什么有效：随机错误在各条链里不相关，正确答案是唯一的收敛点，多数票把偶然的错压下去。代价也直白：采 40 条链就是 40 倍 token，成本线性涨。还有个边界：系统性的错——模型每次都同样误解题意——投票纠不掉，只会把错票投得更集中。

  • 采样多条链，多数投票定答案。
  • 随机错不相关，正确答案是收敛点。
  • 代价：token 线性涨；系统性错投票纠不掉。

06 搜索与验证器

不只多想，还要会挑、会回头。

采样是并行多想，搜索是边想边挑：每一步生成几个候选，验证器打分，好的继续展开、差的剪掉，像走迷宫时每条岔路都先探一眼。验证器分两种：结果验证器只看最终答案对不对，过程验证器给每一步打分——后者更贵，但能更早发现走偏。

搜索的代价是分支数乘链长，算力烧得更快，所以只用在值得的题上：答案可验证的（数学、代码能跑测试），搜索才有意义；开放式问题没有可靠验证器，搜了也不知道挑哪个对。Agent 里的工具调用结果，其实就是一种外部验证器——第 9 天 ReAct 会再讲。

  • 搜索等于每步多候选加验证器打分加剪枝。
  • 过程验证器贵但早发现走偏；结果验证器只看终点。
  • 答案可验证的题才值得搜；开放题缺验证器。
07 常见坑

写出来的推理，不等于真推理。

第一，CoT 的步骤是模型编出来的流畅文本，步骤对不代表真懂，步骤错也可能蒙对答案——不能把“写得像推理”当成“推理对了”。第二，自我纠错没有外部信号时会把对答案改错：模型自己检查自己，等于用同一套概率分布复核自己，错的地方大概率还是错。

第三，CoT 只对足够大的模型有效：Wei 等人发现，100 亿参数以下的模型用 CoT 常常更差——小模型写出的步骤本身就是错的，错步骤还会带偏答案。第四，长链放大错误：链越长，某一步出错的概率越高，还烧更多 token——这就是第 7 天推理优化要解决的问题。

  • 流畅的步骤也可能是错的，步骤对不等于真懂。
  • 无外部信号的自我纠错会把对答案改错。
  • 小模型用 CoT 可能更差；链越长，出错面越大。
08 后端类比与落地

Agent 里的 CoT：Thought 就是草稿纸。

后端类比：CoT 是把一次大计算拆成带中间状态的小步流水线，像把复杂 SQL 拆成 CTE 一步步算、每步结果落临时表。Agent 里 ReAct 的 Thought 字段就是这张草稿纸：模型先写“这一步要查什么、为什么”，再调工具，观察结果再写下一步。

落地清单：给推理设预算（最大步数、最大 token），步数到了就停；关键数字别只信模型复述，用工具重算一遍；可验证的任务配验证器或自洽采样，不可验证的别假装能验；最后记住：CoT 治“想不明白”，第 3 天的幻觉是“不知道还硬编”——分开治。

  • ReAct 的 Thought 就是 CoT 的草稿纸。
  • 设步数与 token 预算；关键数字用工具重算。
  • 可验证的任务才配验证器；CoT 治想不明白，不治硬编。
要点回顾

这课记住什么

  • 一次前向只算一个 token 的概率分布，多步推理塞不进去——模型缺的是放中间结果的地方，不是知识。
  • CoT：先写步骤再给答案，把难题拆成一串简单预测；步骤是模型自己生成的 token，写进上下文继续用。
  • 草稿纸三作用：拆解、记忆（中间结果可回看）、算力（每多一个 token 就多一次前向）。
  • 推理时计算等于更长思考链加更多采样加更深搜索；按难度分配最划算，比 best-of-N 效率高 4 倍以上。
  • 自洽性：同一题采样多条链，多数投票定答案；GSM8K 在 CoT 基础上再涨 17.9 个点，代价是 token 线性涨。
  • 搜索等于每步多候选加验证器打分加剪枝；答案可验证的题才值得搜，开放题缺验证器。
  • 坑：步骤流畅不等于真懂；无外部信号的自我纠错会改对为错；小模型用 CoT 可能更差；链越长出错面越大。
  • 落地：ReAct 的 Thought 就是草稿纸；设步数与 token 预算，关键数字用工具重算；CoT 治想不明白，不治硬编。
自测

Agent 里一道多步算账题，模型直接给答案总错，偶尔还错得不一样。按本课讲的机制，最符合的做法是？

A. 让模型一次直接出答案，并把温度调高多试几次取最顺的一条
B. 要求模型先写出每一步计算再汇总答案，关键数字用工具重算，重要题多采样几条链取多数答案 ✓
C. 把问题拆成更小的 prompt，但每步不留中间结果，各自独立回答
D. 采样 40 条链，取其中最长的一条链的答案
解析：CoT 把难推理拆成简单预测，中间结果进上下文；自洽性靠多数投票压随机错；但关键数字仍要工具重算——投票纠不掉系统性错，链的长度更不代表对错。
证据

论文与文章

  • Chain-of-Thought Prompting Elicits Reasoning in Large Language Models（Jason Wei 等，NeurIPS 2022 2022）
    支持：8 条带步骤的范例让 PaLM 540B 在 GSM8K 上从 17.9% 涨到 56.9%，超过微调 GPT-3 加验证器的成绩；CoT 是规模涌现的能力，100 亿参数以下模型常更差。
    边界：只证明提示方式有效，不改模型；链的步骤是模型生成的流畅文本，步骤对不等于真懂，步骤错也可能蒙对答案。
  • Self-Consistency Improves Chain of Thought Reasoning in Language Models（Xuezhi Wang 等，ICLR 2023 2022）
    支持：同一题采样多条推理链、多数投票定答案；GSM8K 在 CoT 基础上再涨 17.9 个点，SVAMP 加 11.0、AQuA 加 12.2；不需要训练与额外标注，是纯推理时解码策略。
    边界：代价是 token 随采样数线性涨；多数投票只压随机错，系统性误解投票纠不掉。
  • Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters（Charlie Snell 等，arXiv 2024）
    支持：按题目难度自适应分配推理计算，比 best-of-N 基线效率高 4 倍以上；总计算量相当时，小模型配足推理计算可超过 14 倍大的模型。
    边界：14 倍的前提是小模型本身有一定成功率、且在 FLOPs 相当的比较下；最优分配方式随题目难度变化，没有放之四海皆准的固定配比。
