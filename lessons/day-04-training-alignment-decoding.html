训练与对齐、解码策略：概率分布是怎么被练出来、又怎么被调出来的

模型的能力不在某一个参数里，而在两张表里：一张是训练压出来的概率分布，另一张是解码时怎么从分布里取词。前者决定它会什么、偏向什么，后者决定它在一次调用里表现成什么样。训练、对齐、解码不是三个独立旋钮，它们依次塑造同一张分布：预训练定底色，SFT 定格式，对齐定偏好，解码定随机性。

2026-11-04 · 约 18 分钟
第一步

预训练：只学一件事，猜下一个词

预训练的目标函数只有一个：给定前文，预测下一个 token 的概率，猜错就调参数。海量文本跑下来，参数里压进的是语料的统计规律：语法、事实搭配、文体、推理套路。模型没有学到一张事实表，学到的是在什么上下文后，哪个词更可能出现。

这解释了第 3 天的幻觉：压进去的是近似记忆，不是查表。知识越常出现压得越实，长尾越模糊。而且预训练的模型是个续写器，不是助手：你给它指令，它可能续写出更多指令，而不是照做。跟指令的能力，是后面两步加上的。

  • 目标函数：下一个词的交叉熵损失，别无其他。
  • 压进参数的是统计规律，不是真值表。
  • 续写器不等于助手：会续写，不等于会跟指令。
第二步

SFT：用少量示范，把续写器改成助手

监督微调（SFT）给模型看成千上万条“指令—好回答”示范，用同样的下一个词损失训练，只不过训练文本换成了想要的回答格式。数据量比预训练小几个数量级，作用却很大：它把概率质量从“继续写下去”挪向“按指令格式回答”。

关键取舍：SFT 教的是格式与行为模式，不是新知识。示范里没有的知识，SFT 变不出来；示范质量差，模型会学到差的风格。工程上常犯的错，是指望微调补知识——补知识要靠预训练阶段的数据或检索，微调只能决定怎么用已有的知识。

  • SFT 改的是行为分布，不是知识存量。
  • 示范质量决定风格上限，量小但影响大。
  • 想补知识：靠数据或检索，别只靠微调。
第三步

对齐：人类偏好怎么变成梯度

RLHF 分三步：先 SFT，再让人给同一提示的多个回答排序，训一个奖励模型来预测“人会更喜欢哪个”，最后用 PPO 等强化学习算法调模型，让它输出奖励模型打分高的回答。奖励不是真理，是人类偏好的近似器，偏好里的毛病会被一起学进去。

为防模型为骗分走偏，通常加 KL 约束：不许新分布离 SFT 模型太远。代价是两类常见失真：奖励黑客（钻评分空子，如答得长而空洞）和讨好倾向（顺着用户说）。所以对齐不是一劳永逸，偏好数据、奖励模型、约束强度都要一起调。

  • 三步：SFT → 奖励模型 → PPO 调参。
  • KL 约束防走偏，但也会限制改进幅度。
  • 奖励黑客与讨好，是偏好近似带来的固有代价。

解码其一

Temperature：改分布的形状，不改模型

解码时模型先输出每个词的 logit，再除以温度 T 做 softmax 得到概率。T 小于 1 时差距被放大，分布变尖，高概率词更占优；T 大于 1 时差距被压平，分布变坦，低概率词也有机会。T 趋近 0 就是贪心：永远取概率最高的那一个。

所以温度不是“创造力开关”，它是随机性旋钮。写代码、查事实要低温度，因为你要的是最可能的答案；写文案、头脑风暴可调高，因为你要多样性。但低温度不补知识：分布本身错了，取最可能的词也一样错，这正是第 3 天说的坑。

  • 公式：p = softmax(logits / T)，T 在 softmax 之前起作用。
  • T < 1 变尖、T > 1 变坦、T → 0 等于贪心。
  • 低温度压随机、不补知识；高温度给多样、也给幻觉留口子。
解码其二

top-p：按累计概率砍尾巴，候选数随信心伸缩

top-p 又叫 nucleus sampling：把候选词按概率从高到低排，累加到 p 就停，这组词叫 nucleus，只从里面采样。模型自信时一两个词就凑够 p，候选很少；不确定时要凑很多词，候选自动变多。top-k 是固定取前 k 个，不自信时 k 可能不够用，自信时又把不靠谱的词也放进来。

为什么砍尾巴？分布的尾部最不可靠：低概率词大多是训练里罕见的搭配，采样到它们最容易跑偏、重复或编造。温度改形状、top-p 砍尾巴，两者常一起用；但调参时只动一个更容易定位问题，两个一起动，出问题不知道是谁的锅。

  • top-p：取累计概率达 p 的最小词集，再在里面采样。
  • 候选数随信心伸缩，这是它优于固定 top-k 的地方。
  • 温度与 top-p 分工不同：一个改形状，一个截尾巴。

预算怎么分

Scaling Law：参数和数据要一起涨，单涨一边是浪费

训练算力大约是 C ≈ 6ND（N 是参数量，D 是训练 token 数）。固定算力时，损失随 N 和 D 呈幂律下降，但最优分配不是只堆参数：Chinchilla 的结论是两者大致等比增长，经验法则是约 20 个 token 配一个参数。GPT-3 时代只堆参数、数据跟不上，就是在预算上走了弯路。

这个最优只算训练账，不算推理账。推理量大的服务反而愿意“超训”小模型：训练时多花算力、推理时每个请求都便宜。选模型时别只看参数量，要问它训了多少 token、推理成本摊到多少请求上——总账比单项指标重要。

  • C ≈ 6ND：算力、参数、数据三者绑在一起。
  • 经验法则：约 20 token 配 1 参数，单堆参数是浪费。
  • Chinchilla 最优只管训练；推理量大时，超训小模型更划算。
后端类比与坑

把解码参数当运行时配置，把对齐当偏好补丁

后端类比：预训练像建了一个巨大的默认配置库，SFT 与对齐像往上打了两层补丁，解码参数则是每次请求的运行时配置——改配置不改代码，改配置也不改知识。线上出问题先分层：是分布本身错了（训练/数据问题），还是取词方式错了（解码问题），两层修法完全不同。

常见坑有三个：把 temperature 当质量旋钮，来回拧却不查数据与检索；temperature 和 top-p 两个一起大改，出了问题无法归因；以为对齐后的模型更懂了，其实它只是更会按人的偏好说话，知识缺口与幻觉机制原封不动，第 3 天的校验层仍然不能省。

  • 分层定位：分布错了修训练，取词错了修解码。
  • 一次只动一个解码参数，否则无法归因。
  • 对齐改偏好不补知识，校验层不能因对齐而撤掉。
要点回顾

这课记住什么

  • 预训练只优化猜下一个词：压进参数的是统计规律，不是真值表。
  • SFT 用少量示范把续写器改成助手，改行为不补知识。
  • RLHF：人类排序训奖励模型，PPO 朝高分调参，KL 约束防跑偏；奖励黑客与讨好是固有代价。
  • Temperature 改分布形状（logits / T 再 softmax），top-p 按累计概率砍尾巴、候选数随信心伸缩。
  • Scaling Law：C ≈ 6ND，参数与数据等比增长，约 20 token 配 1 参数；该最优只管训练账。
  • 工程原则：解码参数是运行时配置，一次只动一个；对齐不撤校验层。
自测

一个问答服务总编造低频事实，工程师把 temperature 从 1.0 调到 0.2 后仍编造。按本课讲的机制，最可能的原因和下一步分别是什么？

A. 温度还不够低，应调到 0 并换更大模型
B. 温度只改取词随机性、不补知识缺口；应加检索 grounding 与逐条校验 ✓
C. top-p 设得太高，应同时把 temperature 和 top-p 都调到最低
D. SFT 数据太少，应立刻重训一个更大的预训练模型
解析：低温度只压随机、不补知识：分布本身在低频事实上就是糊的，取最可能的词也一样错。正确分层是先承认知识缺口在分布里，再用检索 grounding 补输入、用逐条校验守出口，而不是继续拧解码旋钮。
证据

论文与文章

  • Training Language Models to Follow Instructions with Human Feedback（Long Ouyang 等，arXiv 2022）
    支持：SFT 示范微调、人类排序训奖励模型、PPO 优化的三步 RLHF；1.3B 的 InstructGPT 在人类评估中胜过 175B 的 GPT-3。
    边界：结论来自该论文 API 提示分布上的人类评估，不等于通用能力全面胜过更大模型；本课只取其三步流程与偏好塑造机制。
  • Training Compute-Optimal Large Language Models（Jordan Hoffmann 等，arXiv 2022）
    支持：固定算力下参数与训练 token 应等比增长；70B、1.4T token 的 Chinchilla 在相同算力下全面胜过 280B 的 Gopher，MMLU 约 67.5%。
    边界：该最优只针对训练算力，不含推理成本；本课的超训小模型取舍是基于该边界的工程推论，不属论文原结论。
  • The Curious Case of Neural Text Degeneration（Ari Holtzman 等，ICLR 2020）
    支持：提出 nucleus（top-p）采样：取累计概率达 p 的最小词集再采样；分布尾部不可靠，应在解码时截断。
    边界：实验基于 GPT-2 的长文本生成，不是今天的指令微调聊天模型；本课只取其截尾与动态候选集的机制。
