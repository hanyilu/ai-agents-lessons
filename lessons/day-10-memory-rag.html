AI AGENTS 深入学习 · 第 10 天

记忆与 RAG：给 Agent 装一个会忘、会找的外脑

模型本身没有记忆：权重是训练完就冻结的只读知识，上下文是每次调用从零开始的临时草稿纸。Agent 的记忆只能做在外面——分层存（短期轨迹、长期事实、外部知识），用时按相关性、新鲜度、重要性三信号召回，拼进上下文再让模型读；RAG 是同一套机制的另一半：把知识库切块向量化，查到了再生成。记忆的难点从来不是存，而是写什么、何时忘、查什么——以及记住的东西要能改、能删、能分清是谁的。

2026-11-10 · 约 18 分钟
01 为什么模型记不住

权重是只读的，上下文是从零开始的草稿纸。

每次调用模型都从零开始：它能看到的只有这次传进来的上下文。权重训练完就冻结了，调用不会改权重——昨天聊过的事，不写进这次的输入，模型就不知道。

这不是 bug，是架构：第 1 天讲过，窗口是容量不是记忆；第 4 天讲过，预训练压进参数的是统计规律。Agent 要“记住”，只能把记忆存在模型外面，用时再搬进上下文。

  • 权重只读，调用不改参数。
  • 上下文是唯一的工作记忆，关掉就没了。
  • 记忆是系统设计，不是模型能力。
02 记忆分三层

热的放近处，冷的放远处，各有各的管法。

按存取速度分三层。工作记忆就是当前上下文：正在进行的对话、ReAct 轨迹（第 9 天），快但一关就没。情景记忆是过去的对话与事实：用户偏好、已办事项，存在数据库里。外部知识是 RAG 的知识库：文档、手册、规章，不属于任何一次对话。

分层的理由和后端一样：热数据放内存，冷数据放磁盘。每一层都有自己的写入、读取和淘汰规则，混在一起管，最后一定是窗口先爆、账单先炸。

  • 工作记忆：当前上下文，快、易失。
  • 情景记忆：历史事实，跨会话。
  • 外部知识：共享文档，RAG 管。
03 短期记忆与压缩

轨迹越攒越长，摘要压缩省 token 但丢细节。

短期记忆就是轨迹本身：消息列表按顺序追加，越攒越长。第 1 天的窗口迟早会满，满了就要压缩——最常见是摘要：让模型把旧对话压成一段摘要，再把它当新上下文的开头。

但压缩是有损的：摘要只留“大概意思”，数字、人名、否定词最容易丢；递归摘要一层层压，意思越走越偏。所以关键事实别只靠摘要：偏好、待办、金额要单独存成结构化字段，摘要只负责叙事。

  • 轨迹追加是最简单的短期记忆。
  • 摘要压缩省 token 但丢细节。
  • 关键事实单独结构化存，别混进摘要。
04 长期记忆怎么写

粒度与打分在写入时定，别等召回时再猜。

长期记忆的写入要定两件事：写什么粒度——原句、摘要还是一条提炼的结论；什么时候写——每轮都写，还是对话结束统一写。粒度太细，查回来全是噪音；粒度太粗，又查不到细节。

Generative Agents 的做法值得抄：每条记忆生成时，让模型评一个 1–10 的重要性分（“吃了吐司”1 分，“房子着火”10 分），写入时就带上分数。召回时按相关性、新鲜度、重要性三信号打分，等权相加，分数最高的先进上下文。

  • 写入粒度决定召回质量。
  • 重要性在写入时打分，别事后猜。
  • 三信号：相关、新鲜、重要。

05 RAG 流水线

先查到，再生成：知识在库里，不在参数里。

RAG 是同一套机制的另一半：知识不在参数里，在外部。离线先把文档切成块，每块算一个向量、存进索引；在线把用户问题也算成向量，在索引里找最相似的 top-k 块，拼进上下文再让模型生成。

关键在“相似不等于有用”：向量相似度只量文本像不像，不量能不能回答问题。所以生产 RAG 都在检索后加一步重排：用更强的模型或交叉编码器再筛一遍，只留真正相关的几块，再拼进上下文。

# 离线：切块 → 向量化 → 建索引
chunks = split(doc, size=500, overlap=50)
index.add(embed(c) for c in chunks)
# 在线：问题向量 → 检索 → 重排 → 拼上下文
hits = index.search(embed(query), top_k=20)
top = rerank(query, hits)[:5]
answer = llm(prompt + "\n".join(top))
  • 离线建索引，在线查 top-k。
  • 向量检索看相似，重排看有用。
  • 拼进上下文再生成，答案带引用才可信。

06 召回为什么会错

切块错、向量错、排序错，各有各的修法。

召回错有三类。切块错：块太小，关键句被上下文切散；块太大，窗口塞满无关内容，信号被稀释。向量错：同义词、否定、数字细节在向量空间里长得很像，相似度分不出来。排序错：最相似的块不一定最有用，标题党段落常年排第一。

对策也是三件套：切块按语义边界切（段落、标题），别按固定字数硬切；检索用混合——向量召回加关键词 BM25，两路取并集；最后重排加引用校验，模型回答必须标出来源段落，标不出的不算答。

  • 切块边界决定召回下限。
  • 混合检索补向量盲区。
  • 回答要带引用，标不出处就不信。
07 MemGPT

让模型自己管记忆：主上下文是内存，外面是硬盘。

MemGPT 换了一个思路：别由应用替模型决定搬什么，让模型自己管。主上下文分三块——只读的系统指令、定长的“工作上下文”（存用户偏好这类关键事实）、先进先出的消息队列；外面再挂两个库：完整消息历史的召回库、任意文本的归档库。

搬运靠函数调用：上下文快满时系统发警告，模型自己调函数把重要事实写进工作上下文、把旧消息归档；要查时再调搜索函数捞回来。像操作系统管虚拟内存：主上下文是内存，外部存储是硬盘，函数调用是系统调用。长对话记忆测试里，GPT-4 准确率从 32.1% 提到 92.5%。

  • 主上下文像内存，外部存储像硬盘。
  • 模型用函数调用自己搬运。
  • 满了先警告再归档，不是悄悄丢。
08 常见坑与落地

记忆是私人的、可写的：隔离、可删、会过期。

第一，记忆和 RAG 的治理完全不同：RAG 的知识库是共享的、只读的；记忆是私人的、可写的——多用户系统里记忆必须按用户隔离，删账号要连记忆一起删，记住的偏好也不能跨用户泄露。

第二，记忆会变质：用户的偏好会变、事实会过期，写进去的东西要有时间戳和来源，过期要能更新、错误要能纠正。第三，别把记忆当真理：召回的东西和模型编的东西一样，都要校验——第 3 天的幻觉缓解手段，记忆召回同样适用。

  • 记忆按用户隔离、可删。
  • 事实带时间戳与来源，过期要更新。
  • 召回内容也要校验，别照单全收。
要点回顾

这课记住什么

  • 权重是只读知识，上下文是临时草稿纸——模型本身没有跨调用记忆。
  • 记忆分三层：工作记忆（当前上下文）、情景记忆（历史事实）、外部知识（RAG 知识库）。
  • 写入要定粒度与时机：原句、摘要还是提炼的结论，写错粒度后面都查不回来。
  • 召回按三信号打分：相关性（向量相似度）、新鲜度（指数衰减）、重要性（写入时模型打分 1–10）。
  • RAG 流水线：切块→向量化→检索 top-k→重排→拼进上下文→生成；召回不等于相关，更不等于有用。
  • 切块大小是取舍：块太小丢上下文，太大塞满窗口还稀释信号；边界切断句子最伤召回。
  • 压缩是有损的：摘要丢细节，递归摘要越压越偏；关键事实要单独存结构化字段。
  • MemGPT 式管理：主上下文当内存、外部存储当硬盘，模型用函数调用自己搬运；记忆要能改、能删、能分权限。
自测

用户一周前说过“周五下午不接会”，今天让 Agent 查日历订会。按本课讲的记忆用法，后端最该怎么做？

A. 直接按今天的问题查日历订会，一周前的偏好不用管
B. 先召回“周五下午不接会”这条记忆放进上下文，再查日历，冲突时先问用户 ✓
C. 把一周前的对话全文都拼进上下文再查日历
D. 记住偏好后直接拒绝订会，不用查日历
解析：长期记忆要召回进上下文才能起作用——这条记忆相关性高（都是周五下午的会）、重要性也高；但记忆是参考不是禁令，和当前请求冲突时要先确认，不能直接替用户拒绝；全文拼进上下文既贵又挤占窗口，召回 top-k 就够了。
证据

论文与文章

  • Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks（Patrick Lewis 等，NeurIPS 2020 2020）
    支持：维基百科切成 2100 万条 100 词段落，DPR 编码检索、BART 生成；Natural Questions 上 44.5 分，超过 110 亿参数的 T5（34.5）；换 2016/2018 两版索引不换权重，答案跟着变；11.8% 的答案不在任何召回段落里。
    边界：2020 年配方（BART + DPR + 联合训练），今天多为指令微调模型加现成检索器；只在问答类任务上设了新纪录，结论随任务变化。
  • MemGPT: Towards LLMs as Operating Systems（Charles Packer 等，arXiv 2023）
    支持：虚拟上下文管理：主上下文分系统指令、工作上下文、FIFO 队列三块，外挂召回与归档两个库，模型用函数调用自己搬运；长对话记忆测试里 GPT-4 准确率从 32.1% 提到 92.5%。
    边界：效果依赖模型自己管理记忆的能力与函数调用可靠性；实验用 GPT-4/3.5，基线窗口 8k，结论随模型变化。
  • Generative Agents: Interactive Simulacra of Human Behavior（Joon Sung Park 等，UIST 2023 2023）
    支持：记忆流 + 三信号召回：相关性（向量余弦相似度）、新鲜度（0.995/小时指数衰减）、重要性（模型打分 1–10），三者等权相加；重要性总和超 150 触发反思，取最近 100 条记忆提炼高层结论。
    边界：25 个角色的沙盒模拟（ChatGPT），不是生产记忆系统；访谈评分衡量的是角色可信度，不能直接当生产指标。
